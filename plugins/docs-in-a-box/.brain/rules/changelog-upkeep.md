THE RULE

Give people a readable account of what changed in each version.

What must be true at the end:
- A changelog with an entry for every version, grouped by type, newest first, with release dates, and a statement of whether the project follows SemVer.

How it is handled:
- Write for people, not machines.
- Group changes as Added, Changed, Deprecated, Removed, Fixed, Security.
- Make versions and sections linkable; list the latest version first; show each release date.

WHY

Trigger: A change lands, or a version is released.

Inputs:
- The merged changes and the version scheme.

HOW TO APPLY

Participants: The changelog keeper, developers, and the release manager.

Expectations of the position:
- **Changelog keeper:** accurate and readable; does not paste commit logs.

RELATED

Sources (S-014, S-013): S-014 (primary, read). S-013 (primary, read) for the version scheme.

Roles: changelog-keeper, documenter. Outcomes, not an order: the dependency edges between the roles' skills decide what runs first.
