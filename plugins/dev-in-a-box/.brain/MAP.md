## Purpose

- `code-reviewer`: Reviews a change for whether it improves the overall health of the codebase and says approve, approve with comments or request changes, with reasons the author can act on.
- `code-reviewer-android`: Reviews a change to an Android app for architecture, Kotlin style and the platform's security guidance, and merges in any SQL review the change needs.
- `code-reviewer-iac`: Reviews a change to infrastructure code (Terraform, CloudFormation, Pulumi, Puppet, Ansible) for safety, secrets and the tool's own conventions.
- `code-reviewer-java`: Reviews a change to a Java codebase against the repo's own conventions and the Google Java Style Guide, and merges in any SQL review the change needs.
- `code-reviewer-python`: Reviews a change to a Python codebase against the repo's own conventions and PEP 8, and merges in any SQL review the change needs.
- `code-reviewer-react`: Reviews a change to a React codebase for component structure, state placement and the rules of Hooks, and merges in any SQL review the change needs.
- `code-reviewer-sql`: Reviews queries, migrations and schema changes for correctness and for cost, using the DBA's query review as its evidence.
- `developer`: Implements one unit of work against fixed interface contracts, with tests, on a branch.
- `developer-android`: Implements one unit of work in an Android app (Kotlin first, Java where the repo already uses it), with tests, on a branch, using that stack's own toolchain.
- `developer-java`: Implements one unit of work in a Java or JVM-server codebase (Spring and similar), with tests, on a branch, using that stack's own toolchain.
- `developer-python`: Implements one unit of work in a Python codebase (services, scripts, libraries, data code), with tests, on a branch, using that stack's own toolchain.
- `developer-react`: Implements one unit of work in a React front end (TypeScript first, JavaScript where the repo already uses it), with tests, on a branch, using that stack's own toolchain.
- `developer-sql`: Writes and changes SQL (queries, views, stored routines, migrations, seed and test data) with tests, on a branch, consulting `dba` for optimisation before it ships.
- `spec-analyst`: Turns a product requirement into a technical spec with a test plan and acceptance criteria, resolving gaps before anyone builds.
- `tech-lead`: Routes a technical spec to the right specialist developers, defines the contracts between their units, and takes rejected work back for rework.
