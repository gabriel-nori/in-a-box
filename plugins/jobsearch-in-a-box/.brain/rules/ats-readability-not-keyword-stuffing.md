THE RULE

Applicant-tracking-system work on a resume is about readability and visible truth, never about added claims. Fix the file so a parser reads it intact, and show the terms the profile proves where a search will find them. A posting term the profile does not back stays a reported gap.

- Allowed: one column, standard headings, plain text, repaired ligatures, acronym beside the spelled-out term, a true term in the summary and in a role, a clean file name.
- Not allowed: hidden or white text, a pasted copy of the posting, a skill the profile lacks, a number made up for effect.
- A check result describes the file. It never promises that an employer's system will rank or pass the resume.

WHY

Trigger: someone asks to optimise a resume for an ATS or to raise its keyword score.

Most systems store and search resumes; few reject by score, and a recruiter decides. What fails in practice is unreadable files (ligatures, columns, tables, images, headers) and vocabulary that does not match the recruiter's search. Both are fixed without lying. Stuffing is caught by the first interview question.

HOW TO APPLY

Run `scripts/jobkit.py ats` on the exported file with the keyword list from the requirement match. Fix parse errors at the source and export again. For a backed term the resume omits, show it in context with the profile fact behind it. List gaps beside the result.

EXCEPTIONS

None.
